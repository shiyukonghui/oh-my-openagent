## 补充问题详细说明

### N3: 模型 fallback 链真实性（中优先级）

规划文档 7.2 节 Step 6 列出：
```typescript
fallback: [
  "claude-sonnet-4-6",
  "gpt-5.5-medium",
  "claude-opus-4-7-max",
  "gemini-3.1-pro",
  "glm-5.1",
]
```

**风险**：这些模型 ID 看起来是前瞻性命名（如 `claude-sonnet-4-6` 对应 Claude 4 系列，`gpt-5.5-medium` 对应 GPT-5.x 系列），但截至 2026-05-22，这些模型可能尚未发布或命名不同。若 oh-my-openagent 的模型注册表中无这些 ID，fallback 链将失效。

**建议**：验证当前 oh-my-openagent 支持的模型列表，使用真实存在的模型 ID。

### N4: 本地文件路径泄露（中优先级）

附录 A 包含：
- `file:///D:/Agent/oh-my-openagent/templateCode/open-codesign/...`

**风险**：这是审查者/作者的本地 Windows 开发路径，出现在正式规划文档中说明文档生成流程不规范，且路径对团队其他成员无意义。

**建议**：替换为相对仓库路径（如 `open-codesign/packages/core/src/agent.ts`）或永久链接。

### N11: `loadPromptSection` 机制未定义（中优先级）

6.2 节代码：
```typescript
function buildCodesignPrompt(): string {
  const sections = [
    loadPromptSection("identity"),  // ← 此函数未定义
    // ...
  ]
}
```

**风险**：未说明 `loadPromptSection` 是 oh-my-openagent 现有工具（如 Sisyphus 的 `dynamic-agent-prompt-builder.ts` 中的方法）还是需新建。若需新建，增加了 Phase 1 工作量。

**建议**：明确提示词加载机制——是文件系统读取、构建时内联，还是运行时加载。

### N12: 设计技能 `agent` 字段约束机制未验证（中优先级）

5.1.2 节：
```typescript
export const landingPageSkill: BuiltinSkill = {
  name: "design-landing-page",
  // ...
  agent: "codesign",  // ← 声称仅 codesign 可用
}
```

**风险**：需验证 `BuiltinSkill` 类型是否定义了 `agent` 字段，以及 oh-my-openagent 的技能加载器是否支持按 Agent 过滤。若不支持，此字段无效或导致类型错误。

**建议**：检查 `src/features/builtin-skills/types.ts` 中的 `BuiltinSkill` 接口定义。

### N14: 提示词片段合并冲突风险（中优先级）

6.1 节架构图显示将 11 个提示词片段 + 动态工具说明 + 安全约束合并为一个 prompt。

**风险**：open-codesign 的 11 个提示词片段来自一个 1636 行的 Agent 实现，总长度可能极大。加上 oh-my-openagent 自身的系统提示词开销，可能超出 Claude Sonnet (~200K) 或 GPT-4 (~128K) 的有效上下文窗口，导致提示词截断或性能骤降。

**建议**：测量各片段的 token 数量，设计按需加载策略（如仅加载与当前任务相关的片段）。
